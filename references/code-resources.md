# Plotting code and upstream implementation references

## Entry points

With real results: `python scripts/render_map.py config.json`. With only complete map images:
`python scripts/compose_maps.py config.json`. Run `scripts/check_environment.py` first to check
dependencies, SimHei and Arial; `scripts/requirements.txt` records the tested environment and does not
install anything. Deep PDF inspection optionally uses PyMuPDF and reports plainly when it is missing.

## Configuration example

Paths are relative to the JSON file. The coordinates and temperatures below are examples only; a real
task must replace them with source-confirmed parameters. Runnable synthetic examples are generated by
`demo_gallery.py NEW_DIRECTORY`, are all marked SYNTHETIC TEST and are never real research data.

```json
{
  "width_mm": 180,
  "height_mm": 140,
  "dpi": 300,
  "output_stem": "figure_01",
  "formats": ["png", "pdf"],
  "review": true,
  "svg_outline": false,
  "cvd_threshold": 10.0,
  "cvd_strict": false,
  "mappings": {
    "temperature": {"type":"continuous","variable":"LST","unit":"degC","vmin":18,"vmax":38,"cmap":"YlOrRd"}
  },
  "panels": [{
    "id":"a", "rect_mm":[8,28,164,105], "crs":"EPSG:32649",
    "extent":[450000,3800000,498000,3832000], "label":"a",
    "layers":[{"type":"raster","path":"result.tif","band":1,"mapping":"temperature"}],
    "scale_bar":{"length_m":10000,"location":[0.08,0.12]},
    "north_arrow":{"location":[0.90,0.73],"size_mm":7}
  }],
  "legends":[{"mapping":"temperature","rect_mm":[48,13,90,3],"ticks":[18,23,28,33,38]}],
  "nodata_legend":{"rect_mm":[144,12,30,5]},
  "note":{"rect_mm":[8,2,165,5],"text":"LST (°C)"},
  "caption":"Real figure description, used by the visual review"
}
```

- `rect_mm` is left, bottom, width, height in mm. Maps and legends take explicit positions; map
  containers must not overlap and an inset belongs in a side column by default.
- `extent` is xmin, ymin, xmax, ymax in the display CRS. The map keeps equal coordinate aspect, may
  leave whitespace, and is never stretched to fill its container.
- `mappings` are managed by ID; layers with the same ID share one mapping object and must have a
  matching legend. Out-of-range values raise an error rather than being clipped.
- Panels covering one region may add `comparison_groups: [["a","b","c","d"]]`, which checks that CRS,
  extent and layer mappings match.
- `labels` may provide `[{"xy":[real_x,real_y],"text":"Site A","size":8}]`; it adds text only and never
  moves a feature.
- `coordinates:true` shows projected coordinate ticks. `graticule` may take `longitudes`, `latitudes`
  and `lonlat_bounds` to draw graticule lines; edge longitude and latitude labels are not added
  automatically.
- `svg_outline:true` additionally writes `<stem>.outlined.svg` with glyphs as paths; it needs `svg`
  in `formats` and is refused otherwise.
- `cvd_threshold` changes the colour-vision distance threshold (default 10) and `cvd_strict:true`
  fails the render when a colour pair breaches it. The colour check runs before any file is written,
  so a strict failure costs no artifact, and the whole output set is staged and only committed once
  every check has passed.
- `fonts:{"zh":[...],"en":[...]}` declares an explicit font preference order. SimHei and Arial stay
  the default; the first installed name of each chain is used and nothing else is substituted.
  `GIS_FIGURE_FONT_ZH` / `GIS_FIGURE_FONT_EN` do the same for a machine that has neither font.
- `render_map.py config.json --output-stem other/name` moves the output without editing the file.
  The saved `<stem>.config.json` keeps relative layer paths and records `config_root`, so it replays
  next to the data instead of being pinned to one machine.

## Layer and colour-scale branches

Fixed-class mapping: `{"type":"classified","variable":"LST","unit":"degC","breaks":[18,23,28,33,38],"cmap":"YlOrRd"}`.
Intervals are left-closed and right-open, with the final upper bound included. A result that uses a
different convention must be adapted explicitly; it is never changed automatically.

Categorical mapping:
`{"type":"categorical","variable":"cover","unit":"class","entries":[{"code":1,"label":"Forest","color":"#287A45"}]}`.
Every valid class must be listed, zero may be a valid class, and NoData comes from the data mask.

Vector layer: `{"type":"vector","path":"results.gpkg","layer":"zones","column":"rate","mapping":"rate_map"}`.
Without `column`, set a fixed `color`, `edgecolor` and `linewidth`. The source CRS must exist;
geometries are never repaired or simplified, only transformed for display.

Proportional symbols: add `proportional:{"column":"count","reference_value":100,"reference_area_pt2":40}`
to a vector point layer so area is proportional to value. Both the reference value and area must be
positive. The layer must provide a legend such as
`{"rect_mm":[10,18,40,30],"values":[100,200,300],"unit":"count"}`; the renderer draws reference symbols
with the same ratio and outline style.

Bivariate: the `bivariate` argument of `geo_layers.vector` takes `x_column`, `y_column`, `x_breaks`,
`y_breaks` and `colors`; at most 3x3, with matrix rows ordered low to high in y and columns low to high
in x. Optional `x_label` and `y_label` name the two variables. A missing value in either column paints
the NoData grey and is counted, so the figure needs a `nodata_legend` exactly as a masked raster does.
The layer provides a legend such as `{"rect_mm":[137,18,29,29],"label":"x / y"}`; the renderer
builds the 2-D legend and both axis intervals, and the labels should name the real variables and units.
`map_styles.bivariate_legend` may also be called on its own.

Flow lines: `{"type":"flow","path":"flows.gpkg","column":"volume","reference_value":100,"reference_width_pt":1}`.
Only existing line geometry is used, width is proportional, and nothing is aggregated or routed. A
legend (`rect_mm`, `values`, `unit`) is required and draws lines with the same width mapping. Set
`direction_from_vertex_order:true` only when the user has confirmed that vertex order means flow
direction; arrows then follow the existing geometry and direction is never guessed.

Locator inset: give the second panel its own CRS, extent and layers, and add
`links:[{"detail":"a","context":"b","connect":false}]` to draw the real main-map viewport. The perimeter
is densified before transformation so an extent under a different projection is not mistaken for a
rectangle. `connect:true` may join corresponding corners; check that the line does not cross text. A
locator normally uses only the extent marker.

Composing existing images uses
`{"width_mm":180,"height_mm":120,"output_stem":"composed","panels":[{"image":"main.png","rect_mm":[5,5,125,110]},{"image":"locator.png","rect_mm":[135,70,40,40]}]}`.
Fonts in the source images are not unified automatically. A graphic scale bar keeps its relationship
when the whole figure is scaled, but a numeric 1:xxxxx scale must be recalculated. Images inside a PDF
remain raster. Adding `source_width_mm` (and optionally `source_font_pt` or `source_linewidth_pt`) makes
the report state the size text and strokes will actually print at, and flags anything below the legible
limit. That limit comes from `min_font_pt` in the configuration, or from `--min-font-pt` on the command
line, which wins when it is given. `svg_outline` works here as it does in rendering.

## Geographic calibration and QA

A scale bar samples the horizontal projected path at the anchor for its explicit `length_m`, converts it
through the CRS ellipsoid and calibrates each segment separately. When middle labels crowd, only the
middle labels are hidden and the distance is unchanged; if the endpoints still do not fit, the call
raises an error. The QA record stores the local reference and the scale variation across nine points,
and marked distortion must be stated as locality or omitted.

True north converts the ellipsoidal north at the anchor into the final screen direction and uses
millimetres for size; when it cannot be computed there is no fallback to screen-up. Elements are added
after extent and scale are fixed, and any viewport change requires a complete redraw.

Outputs are the figure, `.config.json`, `.qa.json`, a `.caption.md` and, when review is on, a `.review/`
folder with a page preview, a grayscale copy and the vision prompt. The record holds source SHA-256
values, dependency versions, fonts, mappings and geographic parameters; a source checksum that changes
during rendering raises an error.

Grayscale is not a CVD simulation; text overlap is a candidate only; the PDF font check depends on the
optional PyMuPDF. Output status is pending visual review and is never automatically declared final. AI
image review is performed by the current assistant or an existing tool; no unconfigured external model
API is called.

NOTICE, and record the specific changes.

## Supported scope and acceptance boundaries

The six runnable configurations and their synthetic output are in `assets/examples/`; copy them into the
current task work directory before use. Every JSON can be handed to render_map.py and writes into a
`rendered` subdirectory. The [validation record](validation.md) lists the checks actually executed and
the boundaries.

The common single-map, multi-panel and locator pipelines for prepared projected results are covered, but
this is not a one-stop application for every GIS format and projection.

- GeoTIFF must match the panel CRS; with scale and offset factors, supply physically confirmed results;
  nothing is silently downsampled when a display pixel budget is exceeded.
- NetCDF, multi-band true colour, date-line-crossing global data, unusual polar orientation and display
  reprojection of an existing raster belong in a dedicated GIS tool before layout. The current backend
  does not accept them directly.
- No classification, KDE, flow aggregation, slope or hillshade computation.
- Tests use clearly labelled synthetic data and have not been accepted against a user's real results.
  Never describe passing synthetic tests as covering every geographic scenario.
- SimHei and Arial are fixed; complex formulae, special symbols and journal page rules need their own
  check.
